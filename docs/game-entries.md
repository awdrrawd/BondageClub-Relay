# BC 快速入口、備援與檢查

## 版本來源

`https://www.bondageprojects.com/club_game/` 是主要來源，也是首頁永遠保留的連結。Worker 解析 `href` 或字面值 `window.location` 指派，只保留 HTTPS 遊戲版本路徑，不執行遠端腳本，也不依賴 `style` 或 class。

2026-09-26 實測：官方入口列出 R132；America 根頁的 meta refresh 仍指向 R114，Europe A 根頁 404、Europe B 與 Asia 根頁是歡迎頁，Asia `/club/` 亦為 404。不能將根網址當作保證追蹤最新版的固定入口。這只是當次觀察，未確認官方內部發布流程。

同日補充實測：四個 **R131 遊戲入口**都回傳 HTTP 200 的舊版提示頁，再用 `meta http-equiv="refresh"` 指向 R132。Europe 的 `../../R132/BondageClub/` 與 Asia 的 `../R132/` 必須依當前頁 URL 解析。`fetch` 的 HTTP 導向功能不會處理這種 HTML 導向；本專案使用 HTMLRewriter 讀取，不執行頁面腳本，也不必等待 refresh 的兩秒延遲。

鏡像倉庫的 `Scripts/Game.js` 以 `var GameVersion = "R132"` 宣告程式版號，`index.html` 會載入該腳本；`CHANGELOG.md` 與 `changelog.html` 也列出 R132。這些是該份原始碼的版本資訊，不是所有官方通道都已部署該版的證明，因此不拿倉庫版號直接組合「已上線」網址。

## 備援設定

`src/game-config.js` 的 `fallbackEntries` 是站方預設清單，例如：

```js
{name: 'Asia Server', url: 'https://www.bondage-asia.com/club/{version}/'}
```

`{version}` 包含 R，例如 R132。無須逐月修改模板。`fallbackVersion` 預設空字串，不將目前月份或倉庫開發版本猜成已部署版本。若官方多個通道正處不同版本，不推定單一共用版本。每筆站方預設另有 `seedUrl`，在模板無法代入版本時使用已知歷史入口；R131 是備援起點，並非硬寫的最新版。各通道獨立追蹤，不將某一通道的結果套用到其他通道。

一般顯示官方清單；偵測失敗時，Worker 嘗試最近一次成功清單，瀏覽器另保存一份備份，兩者最多接受 7 天舊資料。Worker Cache API 可能提前清除資料，瀏覽器儲存亦可能被停用；備份不是永久資料庫。沒有清單且沒有版本時，預設入口從 `seedUrl` 開始檢查。沒有 seed 的自訂模板仍顯示等待版本，官方入口永遠保留。若官方刪除歷史頁或不再維護導向，seed 無法保證永遠有效；屆時可更新起點或指定備援版本。

頁面的「自訂與備援入口」讓使用者輸入每行 `名稱 | HTTPS 網址`，最多 12 筆，只保存於目前瀏覽器；不寫入站方設定。模板版本依序採用當次官方共用版本、使用者備援版本、上次清單共用版本、站方 `fallbackVersion`。自訂入口與官方入口去重後一同顯示。自動偵測失敗且使用者有指定備援版本時，以備援模板重新建立入口，避免仍只提供舊版。

當 API 未取得即時官方清單時，瀏覽器會比較 API 備份、目前清單與本機成功備份的時間，優先保留 7 天內較新的成功清單；API 回傳的歷史起點不會蓋過有效的成功備份。

手動填完整版本網址會保留為設定中的起點。檢查若確認 HTTP／meta refresh 導向到可辨識的遊戲頁，卡片直連採用目的地，顯示例如 `R131 → R132`，本機圖示檢查亦改用目的地；未確認的導向不改寫連結。按「恢復站方預設」清除自訂清單與手動版本，不清除成功清單備份。HTML 變更超出已支援的導向格式時，仍可能需要修正解析器。

## 入口狀態

- `/api/game-link-status?url=...`：Worker 以 GET 取得 HTML，檢查標題 `Bondage Club` 與 `Scripts/Common.js`。HTTP 與 meta refresh 導向共用最多五跳限制，攔截循環、多重 refresh 與未核准的目標。只有最後的遊戲頁才算成功；結果含實際目的地、URL 版號與導向紀錄。每個入口結果快取 60 秒，總逾時 8 秒、每頁內容上限 512 KiB。HTTP 404／410 顯示頁面不存在；403、其他錯誤、逾時、非遊戲頁與無法確認的導向顯示未確認。
- 本機：瀏覽器用 Image 載入入口下的 `Icons/Logo.png`，7 秒逾時。成功表示該小型素材能載入；失敗可能是網路、瀏覽器政策、擴充功能、資源不存在或逾時，不能一概判定網站離線。
- 兩個結果分開顯示，並各列檢查時間。站方網路不等於訪客網路；兩者都成功亦不能證明登入、遊戲 Socket 或全部素材正常。
- 開頁與更新清單後自動檢查，也可按「重新檢查」。前端同時最多檢查兩個入口，變更設定後會中止舊一輪；無背景輪詢。

只有 `probeHosts` 中的 HTTPS 網域（及 www 形式）可接受檢查；拒絕自訂埠、帳密、query 與非遊戲路徑。伺服器不提供任意網址代理、不轉送訪客 cookie、不回傳遠端頁面內容。新官方網域可列為連結，但必須另外加入此白名單才可檢查；Loader 與中繼 Origin 白名單也需個別維護。

## 驗證

`npm test` 包含 Miniflare 實際 HTMLRewriter／Cache API 測試、模擬版號增加與通道增減、舊清單備援、HTTP 錯誤及導向限制，以及前端自訂模板／本機素材檢查／備份過期測試。執行 `npm run build` 會輸出兩個 API 的 Pages 路由及共用設定模組。
